# 版本变更说明（中文版）

本文档用于说明当前版本相对上一版 GitHub 提交所做的主要改动，重点面向研究协作、项目汇报和老板快速理解，不追求逐行代码细节，而强调“系统能力发生了什么变化”。

---

## 1. 整体变化概览

这次版本的核心变化，不是单纯修几个 bug，而是把系统从：

- 以自由搜索为主的因子挖掘流程

推进到了：

- 以 **PDF 研报输入**
- **结构化研究假设提取**
- **Crypto 市场机制迁移**
- **分阶段假设进化**

为主的新流程。

简单说，系统开始具备了“先读研报、再迁移到加密场景、再围绕同一条研究主线做实验”的能力，而不是完全依赖模型自由发散。

---

## 2. 输入层能力升级

### 2.1 新增 PDF 研报输入

系统现在支持直接读取 PDF 研报，并将其作为因子研究的上游输入。

新增能力包括：

- 从 PDF 提取正文文本
- 识别原始研报来源
- 将研报内容组装成统一的 research report payload
- 将数据集可用特征与验证目标一起传入第一个 agent

这使得系统不再只接受一句简单的 initial direction，而可以从完整研究材料出发。

### 2.2 新增研报文本清洗

为了解决券商研报中常见的大量噪音文本，这次加入了 `report_cleaner` 预处理层。

已处理的噪音类型包括：

- 免责声明
- 法律声明
- 风险提示
- 信息披露
- 联系人 / 电话 / 邮箱
- 评级说明
- 部分页眉页脚
- 竖排单字 OCR 残片

这一层的意义是：

- 让第一个 agent 看到的文本更接近研究正文
- 降低研报尾部披露内容对假设抽取的污染

---

## 3. 第一个 Agent 的角色变化

原本第一个 agent 更像“自由生成 hypothesis 的模型”。

现在它的角色已经升级成：

- 研报解释器
- 研究逻辑提取器
- Crypto 迁移器
- Proxy 重建规划器

### 3.1 结构化输出增加

现在第一个 agent 会显式输出：

- `thesis`
- `mechanism`
- `crypto_adaptation_summary`
- `proxy_reconstruction_plan`

这意味着第一步的产物已经不是一句模糊假设，而是一份更像研究员写出的结构化摘要。

### 3.2 防止直接照搬 A 股机制

第一个 agent 现在会区分：

- 哪些原始市场机制是可迁移的
- 哪些是 A 股制度特有、不能直接照搬的
- 在 Crypto 场景下应该如何重写

这对“把传统量化研报迁移到加密货币因子挖掘”非常关键。

---

## 4. 第二个 Agent 的研究流程变化

### 4.1 第一轮不再自由乱搜

第二个 agent 现在会在第一轮优先做：

- `base_reconstruction`

也就是先围绕研报提取出的核心 thesis，做朴素复现，而不是直接在大空间里自由搜索表达式。

### 4.2 后续轮次改成阶段驱动

之前 loop 更像按轮次反复尝试，现在已经改成：

- `base_reconstruction`
- `parameter_tuning`
- `resonance_filtering`
- `thesis_revision`

这种 **research stage** 驱动模式。

这意味着：

- `loop_count` 仍然只是预算
- 真正决定下一轮做什么的，是上一轮结果对应的研究阶段

这样既保留了灵活性，又避免了每一轮都无约束漂移。

---

## 5. Feedback 语义变得更清楚

这次没有重写 feedback agent 框架，但补强了它的语义判断。

现在它会尽量区分：

- `thesis_invalid`
- `proxy_weak`
- `parameter_not_tuned`
- `implementation_unstable`
- `direction_mismatch`

这比之前“结果不好就换方向”的风格更像真正的研究诊断。

### 5.1 Thesis revision 边界更严格

新增了一条重要约束：

- 不能因为单轮弱结果，就把原 thesis 从 `reversal` 直接改成完全相反的 `continuation`

也就是说，现在允许修 hypothesis，但不鼓励无边界漂移。

---

## 6. 工程稳定性增强

### 6.1 Hypothesis JSON 解析更稳

之前最容易炸的一环之一，是 hypothesis agent 的 JSON 解析。

现在增强了：

- 对 fenced code block 的提取
- 对 `<think>` 内容的清洗
- 对控制字符、尾逗号、异常引号的修复
- parse failure 后的重试

这显著降低了“模型其实回了东西，但因为格式脏导致整轮失败”的概率。

### 6.2 LLM 错误观测更清楚

这次还补了 LLM gateway / retry 观测能力。

现在日志里更容易看到：

- retry 是否发生
- provider 是否短时不稳定
- 是否可能是 rate limit / 上游网关异常
- 更完整的错误细节

也就是说，后面再出 `Connection error`，我们不需要再纯靠猜。

---

## 7. 数据与评估口径进一步对齐

当前系统已经按本地 parquet 数据的真实 schema 对齐：

- 因子输入只使用 parquet 中真实存在的非 `fwd_*` 特征
- 验证目标统一使用 `fwd_returns_24h`

同时报告中新增展示：

- Sharpe
- Drawdown

让最终研究产物不只看 IC / Rank IC，也能看到更接近组合表现的指标。

---

## 8. 报告生成器变化

报告生成器这次也升级了，重点是：

- 报告整体结构改成中文版
- 增加“研报抽取摘要”部分
- 增加“研究流程图”
- 展示每轮：
  - 本轮假设
  - 本层实验设计
  - 因子与表达式
  - 反馈与结论
- 增加跨轮指标总表
- 在总表中加入 Sharpe / Drawdown

这让报告不再只是日志拼接，而更像一份可阅读、可汇报的研究记录。

---

## 9. 这次版本的真正价值

如果只看短期 IC / Rank IC，这一版未必总是比之前“自由乱挖”的版本更好。

但这次版本真正提升的是：

- 研究流程的一致性
- 假设与因子之间的因果链条
- 对 bug 的可诊断性
- 对研报输入的利用能力
- 对失败结果的解释能力

简单说，这次版本是在打地基：

- 让系统从“偶尔撞出高分但不稳定”
- 走向“过程更可信、输出更可解释、后续更容易继续研究”

---

## 10. 下一步建议

基于当前版本，后续最值得继续推进的方向包括：

1. 进一步把报告正文内容也逐步中文化
2. 给 `parameter_tuning` 增加复杂度上限，避免表达式过快膨胀
3. 继续强化 feedback 对 thesis / proxy / parameter 的区分
4. 视需要增加多模态或 OCR 能力，提升图表型研报的可利用度

---

## 一句话总结

这次版本最大的变化，不是“又多挖了几个因子”，而是：

**我们把系统从一个偏自由搜索的因子挖掘器，推进成了一个能够读取研报、迁移到 Crypto、按研究阶段持续进化的研究型工作流。**
